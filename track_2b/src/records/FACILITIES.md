# Hospital search and selected locations

In the record review form, enter the hospital/clinic name and town, then click **Search hospitals** or press Enter in that search field. Results appear inside Comfort with name/address. **Choose this hospital** fills the issuing facility name and Google Maps coordinate pin. **Confirm these details** saves the selection with the reviewed metadata. The search does not open another site or require copying a link. **View pin** is an optional explicit Google Maps navigation.

Search uses open map data, not Google's hospital directory. A result's coordinates represent its mapped point/centroid, not a verified entrance. Coverage and names may be incomplete; users choose the correct branch. Existing records can retain a facility name without a location. Changing the facility name removes the pending location; changing the search text alone does not silently change the already selected place. Removing the location preserves the facility name.

POST `/api/workspaces/{workspace_uuid}/facilities/search/` accepts only `{"query":"Hospital name, town"}` (3–180 characters). It requires the session, CSRF and continuing `review_metadata` plus `read_workspace_records` capabilities, including a check after lookup. No source bytes, patient identifiers, session/token or original metadata are sent to the provider. Only the explicit public place query is sent. Provider response bodies/queries are not logged by this adapter. Search results are normalized to bounded healthcare places, valid coordinates and canonical Google Maps links. Labels are rendered with textContent.

The public demo uses [Nominatim](https://nominatim.org/release-docs/latest/api/Search/), following its [usage policy](https://operations.osmfoundation.org/policies/nominatim/): explicit end-user searches only, no autocomplete, one request per second across the app, identifying User-Agent, caching and attribution. A PostgreSQL gate serializes outbound requests across web workers; a seven-day cache keys the endpoint/query hash and retains only normalized public place results. Errors commit the rate gate and do not retry automatically. Requests reject redirects, retain TLS verification and have a six-second timeout/256 KB response limit. Searches should contain public hospital names/towns only, never confidential information.

UI displays © OpenStreetMap contributors with [ODbL attribution](https://www.openstreetmap.org/copyright). Selected data also retains provider/source ID/source URL and attribution. The Google Maps link is generated from the selected coordinates using [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started); no Google Places API or Google API key is used.

Results include a signed 15-minute selection token bound to the requesting account/workspace. Review accepts `facility_selection` alongside the existing three metadata values. A valid choice must match the reviewed facility name; a null selection explicitly clears the location. The server derives the stored location and pin from the signed result, not client-supplied coordinates. MetadataAssertion retains the complete location on the immutable patient-confirmed facility assertion. Head changes keep revision/conflict checks; packet snapshots retain the exact selected assertion/location after later corrections. AI output schema remains unchanged and cannot populate locations. Database checks restrict location fields to patient facility assertions; append-only history guards remain in force.

Legacy `facility_maps_url` API clients remain supported: valid Google Maps URLs can be supplied; an omitted location retains the old pin only while the facility name remains unchanged. An explicit null removes it. The current UI uses selection rather than pasted links.

`FACILITY_SEARCH_URL` can be changed without code changes. For an on-premise/air-gapped submission, provision a local Nominatim service/data extract and set a local endpoint; this public demo lookup is an external runtime dependency when used. Configured local HTTP hosts are localhost, 127.0.0.1, host.docker.internal and facility-search; other endpoints require HTTPS. The lookup is optional for record storage/review; provider failure retains records. No self-hosted geocoder, production capacity or complete sovereign deployment is claimed here.

Coverage includes typed pins, correction history, frozen packets, forged/expired/cross-account selections, stale review, revocation, CSRF, healthcare filtering, malformed coordinates, caching, provider failure and global rate limiting.
